ARCHITECTURE

How it works

⬡

Transaction captured

Bank systems collect dozens of signals the moment a card is used — merchant, device, location, velocity, account history.

→
⬡

PCA transform

Raw signals are compressed into 28 anonymous components (V1–V28) via PCA. Customer data is protected. Patterns are preserved.

→
⬡

API inference

Your system calls POST /predict with 30 fields. The model scales, predicts, and returns a risk level in milliseconds.

→
⬡

Risk decision

Response includes fraud probability, risk level (LOW / MEDIUM / HIGH), and a human-readable decision string.

MODELS

Two models, two tradeoffs

Random Forest
rf

100 decision trees with balanced class weights. Conservative and precise — when it says fraud, trust it. Best for systems where false alarms are costly.

Precision
96%
Recall
74%
F1 Score
84%
Misses ~26% of fraud. 3 false alarms per 56,864 legit transactions.
Logistic Regression
logistic

Linear model with balanced weights. Aggressive catch rate — flags almost all fraud but generates more false positives. Best for high-stakes fraud prevention.

Precision
6%
Recall
90%
F1 Score
12%
Catches 88/98 fraud cases. Flags 1,290 legit transactions as suspicious.
